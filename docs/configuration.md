# Справочник конфигурации

Дополняет README. Полный пример — `configs/default.toml`; значения всех полей — `src/arpo_lab/config.py`. Дробные длительности в секундах поддерживаются.

## model

`base_url` — адрес API с `/v1` без `/chat/completions`; `name` — идентификатор модели или путь. `allow_remote=false` принимает только localhost/127.0.0.1/::1. В URL не должно быть логина и пароля. `api_key_env` — имя переменной окружения с ключом, ключ не пишется в TOML.

`timeout_s` — таймаут отдельного HTTP запроса; `max_retries` — число повторов после сетевой ошибки, 408/429/5xx; 4xx и некорректные ответы не повторяются. `retry_delay_s` — пауза. Все попытки учитываются в общем max_requests. Отключите ретраи (`0`), если хотите вручную контролировать каждую попытку.

`max_tokens` — максимальный выход одного запроса; `temperature`, `top_p`, `seed` — параметры генерации. `require_usage=true` останавливает обработку ответа без точных prompt_tokens/completion_tokens. `false` позволяет продолжить, помечая суммы неполными.

Дополнительные настройки, поддерживаемые вашим сервером:

```toml
[model.extra_body]
top_k = 20
min_p = 0.0
repetition_penalty = 1.05

[model.extra_body.chat_template_kwargs]
enable_thinking = false
```

Не все модели и серверы поддерживают эти поля. extra_body не может заменить историю, модель, stream, tools, n и max_tokens. Встроенный агент использует stream=false для надёжного usage. Измерение TTFT и аппаратной энергии пока не реализовано; `model_time_s` — полная длительность HTTP вызова.

## agent

`protocol="native"` — обычный режим инструментальных вызовов. Сервер должен поддерживать tools/tool_calls для выбранной модели. Доступны write_file, read_file, list_files, finish и, при allow_run=true, run_command. Токены определений инструментов входят во входной usage.

`protocol="files"` — основной ACOM профиль. Модель получает начальные файлы, возвращает полные замены в блоках `file:relative/path`, без JSON команд. После каждого ответа обёртка выполняет независимые проверки и передаёт диагностику. Для многокомпонентной задачи включайте в context_files все необходимые контракты, незавершённые исходники и публичные SDK заголовки. Файловый доступ и компиляцию выполняет обёртка; модели не передаются инструменты.

`protocol="qwen-xml"` — дополнительный инструментальный профиль Qwen3-Coder с MLX. Передаёт tools, запрашивает исходные token ID через `logprobs=true`, декодирует локальным токенизатором и самостоятельно разбирает XML вызовов. Требует локальный каталог модели и MLX API с ID токенов; обычный API с текстовыми logprobs не подходит. Данные usage сохраняются без пересчёта. Для других моделей и API доступен native; менять протокол нужно до парной серии.

`protocol="blocks"` — переносимый режим без штатного tool calling. Файл открывается строкой из трёх обратных кавычек с `file:relative/path.c`, содержит буквальный текст и закрывается тремя кавычками. Для Markdown с вложенными тройными кавычками используйте четыре. Ответ заканчивается блоком `json` с actions/done/summary.

`protocol="single-file"` — режим для одного изменяемого исходника, используется также в ACOM примере abs с общим готовым каркасом. Задайте `fallback_file="SourceFiles/AbsMethods.c"`. Модель возвращает ровно один блок кода без пояснений; обёртка сохраняет полный файл и запускает проверки. Инструменты модели не передаются. После провала модель получает диагностику и заменяет весь файл. Для нескольких изменяемых файлов выбирайте files, native или blocks.

`fallback_file=""` — по умолчанию отключено. Если для однофайловой задачи указать `solution.c`, единственный обычный блок C кода в текстовом ответе native режима автоматически сохраняется в этот файл и проверяется. Несколько блоков не выбираются произвольно. Для компонентов с несколькими исходниками используйте инструменты и оставляйте fallback пустым.

`system_prompt` — строка (можно многострочная TOML). Изменённый текст сохраняется в run.json. Если не переопределён, выбирается подходящий текст для протокола. Не добавляйте туда скрытые требования лабораторной, если изучаете эффект подробности пользовательского промпта.

`workspace_manifest=true` включает в начальный контекст список исходников и заголовков seed. `context_files=["SharedFiles/*.h", "HeaderFiles/*.h", "SourceFiles/*.c"]` добавляет буквальное содержимое выбранных файлов. Относительные glob шаблоны не могут выходить за workspace. В ACOM профиле обе настройки включены, в общих defaults выключены. Этот общий контекст одинаков для двух веток и входит во входные токены; не помещайте туда решение или скрытые требования из подробного промпта.

`max_requests`, `max_total_tokens`, `max_wall_s` — суммарные бюджеты запуска, включая resume. Время ожидания пользователя между сессиями не расходует активный бюджет. `max_actions_per_response` ограничивает один ответ, `max_context_chars` — длину сериализованной истории. Последний не является длиной контекста в токенах модели; реальное окно задаётся выбранной моделью.

`max_identical_replies=3` останавливает цикл после трёх подряд идентичных ответов,
если независимые проверки по-прежнему не проходят или формат ответа неверен. Статус — `stalled`;
токены и время всех повторов сохраняются. Значение `0` отключает ограничение.
Уточнение через resume сбрасывает только счётчик одинаковых ответов, сохраняя общий бюджет и стоимость.

## tools

`allow_run` отключает команды модели, сохраняя независимую проверку. `allowed_executables` — точные первые элементы argv, например `clang`. Команды без shell, поэтому `&&`, pipes и shell expansion не работают. Не добавляйте интерпретаторы и shell без необходимости; с `sandbox=off` они снимают практически все ограничения выполнения.

`sandbox` — required/auto/off. `timeout_s` ограничивает процесс; по таймауту завершается вся его группа. `max_output_chars` обрезает возвращаемый вывод и отмечает обрезание. `max_file_bytes` ограничивает чтение/запись агентом; `max_workspace_bytes` — общий размер перед записью (внешние программы сами могут создать больше); `max_list_entries` — число элементов одного листинга.

`read_only_paths=[".sdk", ".arpo-build.py", "SharedFiles"]` запрещает запись файловыми инструментами и дочерними процессами sandbox в выбранные относительные пути. В lab-init SDK, сборщик и manifest защищены; фиксированный контракт примера abs также защищён. При sandbox=off запрет для дочерних процессов не действует; внешний сборщик дополнительно сверяет SDK SHA256.

Процессы получают минимальное окружение без API ключа и пользовательского HOME, с временными файлами в workspace. Для своего toolchain можно добавить явные переменные:

```toml
[tools.environment]
CC = "clang"
CFLAGS = "-std=c89 -pedantic-errors -Wall -Wextra"
```

Эти переменные сохраняются в отчётах и не подходят для секретов. sandbox читает системные пути и виртуальное окружение, пишет только workspace. Дополнительные разрешения инструментальной цепочки задаются в `sandbox_profile` исходного кода.

## validation и experiment

`validation.commands` — массив массивов argv. Скрипты остаются вне workspace, вывод становится обратной связью. `timeout_s` — на команду, `feedback_chars` — лимит обратной связи. Общий дедлайн агента ограничивает также проверки. Отпечатки внешних файлов аргументов фиксируются до генерации, сверяются перед каждой проверкой и после исполнения. Изменённый между итерациями validator не принимается.

`experiment.repeats` — число пар. `order`: alternate/short-first/detailed-first. `warmup` — отдельный короткий запрос до первой пары. Параметры всех повторов одинаковы, каждый имеет отдельный workspace и историю. Для проверки на разных моделях запускайте отдельные серии.

## pricing и report

`input_per_million`/`output_per_million` — неотрицательные тарифы за миллион токенов, `currency` — подпись. Они не меняют модель и не отправляются провайдеру. Для MLX оставьте нули.

`report.title`, `author`, `group` задают Word/Markdown титульные данные. Файл `--notes` позволяет переопределить эти поля и задать task, algorithm, complexity, improvements, testing, integration, visualization, conclusion, references. Незаданные описания остаются явно обозначенными полями для заполнения, а не выдуманным текстом.
